01 — The Core Problem

VoiceOS has no PATH

VoiceOS launches MCP servers with a minimal environment — no PATH, no shell, no env vars. Every error we hit across three integrations was the same root cause showing up differently:

ErrorCause
ENAMETOOLONGInline env vars (KEY=value command) in the launch field — VoiceOS can't parse them
EACCESScript not executable — chmod +x start.sh was never run
env: node: No such file or directorynode or npx not in VoiceOS's PATH, even when called with a full path
Connection closed / -32000Any of the above — check the Logs view in VoiceOS for the specific line
✓
The fix for all of them is the same: a start.sh wrapper script that sets PATH and env vars before launching your server.
02 — The start.sh Pattern

The wrapper every integration needs

Never put commands or API keys directly in the VoiceOS launch field. Always use a start.sh wrapper that handles PATH and secrets first.

start.sh
#!/bin/bash # 1. Prepend full node bin path — VoiceOS has no PATH export PATH="/Users/yourname/.nvm/versions/node/vX.X.X/bin:$PATH" # 2. Set secrets here — never inline in VoiceOS launch field export MY_API_KEY="your_key_here" # 3. Launch your server exec npx tsx /path/to/my-server.ts

Find your node version and path:

Terminal
ls ~/.nvm/versions/node/ # e.g. v24.14.1 # full path: /Users/yourname/.nvm/versions/node/v24.14.1/bin
⚠
Even when calling npx with a full path, it still calls bare node internally. The export PATH line is not optional — without it you'll get env: node: No such file or directory regardless.
03 — Checklist

Before connecting to VoiceOS

Run through this for every new integration:

  • Use a start.sh wrapper — never put commands directly in VoiceOS
  • export PATH="/Users/yourname/.nvm/versions/node/vX.X.X/bin:$PATH" at the top of start.sh
  • Run chmod +x start.sh — required or VoiceOS throws EACCES
  • No spaces in the folder path — causes ENAMETOOLONG
  • Use the full absolute path in the VoiceOS launch field
  • API keys go in start.sh, not the VoiceOS UI
  • Add start.sh to .gitignore — never commit secrets. Commit start.sh.example instead
04 — Three Integration Types

Pick the right pattern

Type 01
Local TypeScript MCP Server
TypeScript
Build your own tools. Best for macOS automation, API wrappers, and custom workflows. Recommended — most reliable across machines.
my-server.ts
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js"; import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js"; import { z } from "zod"; const server = new McpServer({ name: "my-server", version: "1.0.0" }); server.tool( "tool_name", "What this does. Include example voice phrases.", { param: z.string().describe("What this param is") }, async ({ param }) => ({ content: [{ type: "text", text: `Result: ${param}` }] }) ); await server.connect(new StdioServerTransport());
start.sh
#!/bin/bash export PATH="/Users/yourname/.nvm/versions/node/v24.14.1/bin:$PATH" export MY_API_KEY="your_key_here" exec node "$(dirname "$0")/node_modules/.bin/tsx" "$(dirname "$0")/my-server.ts"
Install
npm install @modelcontextprotocol/sdk zod tsx typescript cp start.sh.example start.sh chmod +x start.sh
Type 02
Remote Hosted MCP (via mcp-remote)
mcp-remote
The service hosts their own MCP server — you just bridge to it. Works for Intercom and any service with an MCP endpoint. No server file needed.
start.sh
#!/bin/bash export PATH="/Users/yourname/.nvm/versions/node/v24.14.1/bin:$PATH" export API_TOKEN="your_token_here" exec npx mcp-remote \ https://mcp.example.com/mcp \ --header "Authorization:Bearer ${API_TOKEN}"
💡
That's the entire integration. No package.json, no npm install — just start.sh and your API token.
Type 03
Python MCP Server (FastMCP)
Python macOS caveat
Simpler for quick scripts — no npm, no package.json. But macOS ships Python 3.9 and FastMCP requires 3.10+. You need Homebrew Python.
Setup (Homebrew)
brew install python@3.12 /opt/homebrew/bin/python3.12 -m pip install mcp
my-server.py
from mcp.server.fastmcp import FastMCP mcp = FastMCP("my-server") @mcp.tool() def tool_name(param: str) -> str: """What this does. Include example voice phrases.""" return f"Result: {param}" if __name__ == "__main__": mcp.run(transport="stdio")
start.sh
#!/bin/bash export MY_API_KEY="your_key_here" exec /opt/homebrew/bin/python3.12 /path/to/my-server.py
05 — Tool Design Tips

Writing tools VoiceOS actually understands

These come from reverse-engineering VoiceOS's source code. The LLM uses your tool descriptions to decide which tool to call — treat them like voice command documentation.

Descriptions are everything
Write descriptions like you're writing for a voice assistant. Include the purpose AND example phrases the user might say.
Keep responses short
VoiceOS reads tool output aloud. Return concise summaries, not data dumps. "Opened Spotify" beats a JSON blob.
Human-readable errors
VoiceOS reads errors aloud too. Return "App not found: Notionn" — not a stack trace or a 500 error string.
Name your server correctly
The name field in McpServer should match your integration name — VoiceOS uses it internally for identification.

Description example

Bad vs Good
// ❌ Too vague — VoiceOS won't know when to call this "Opens an app" // ✅ Detailed — includes purpose and example phrases "Instantly open a macOS application by name or alias. Say: 'open Chrome', 'launch Spotify', 'open Cursor', 'open Slack'. Aliases: browser=Chrome, code=Cursor, messages=Beeper, vpn=ProtonVPN."

07 — Claude Desktop

Claude Desktop is easier

Unlike VoiceOS, Claude Desktop handles env vars natively via the env key. No wrapper script needed.

macOS: ~/Library/Application Support/Claude/claude_desktop_config.json

Local TypeScript server
{ "mcpServers": { "my-integration": { "command": "/path/to/node_modules/.bin/tsx", "args": ["/path/to/my-server.ts"], "env": { "MY_API_KEY": "your_key_here" } } } }
Remote MCP (mcp-remote)
{ "mcpServers": { "intercom": { "command": "npx", "args": ["mcp-remote", "https://mcp.example.com/mcp"], "env": { "AUTH_HEADER": "Bearer your_token_here" } } } }
💡
Restart Claude Desktop after saving the config file.
08 — What VoiceOS's Docs Miss

The official docs aren't enough

VoiceOS's own build guide says:

  • • TypeScript: npx tsx /path/to/server.ts
  • • Python: python3 /path/to/server.py

Both fail in practice. Here's what's missing:

What docs sayReality
npx tsx server.tsnpx not in VoiceOS PATH — use start.sh with export PATH
python3 server.pySystem Python 3.9 — FastMCP needs 3.10+, install via Homebrew
(not mentioned)chmod +x start.sh is required — EACCES without it
(not mentioned)Spaces in folder path break the launch command
(not mentioned)Inline env vars in launch field cause ENAMETOOLONG
✓
The start.sh wrapper pattern in this guide solves all of it.
